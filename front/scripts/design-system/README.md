# Design system workbench scripts

Run from `front/` with Node 24 (the repo's engines requirement). Scripts run through `tsx`. They read the repo and write only under `.storybook/static/` and `app/design-system/tokens/`; none changes platform code.

- `npm run storybook` / `npm run build-storybook`: `ds:prepare`, then Storybook dev on port 6006 or `storybook build`. The dev server also serves the workbench at `/workbench/` and an MCP server for agents at `/mcp` (`@storybook/addon-mcp`).
- `npm run ds:tokens`: generate `tokens.css`, `tokens.ts` and `tokens.meta.json` in `app/design-system/tokens/` from `tokens.source.json` (W3C DTCG; `$value` is the value the code renders now, `$extensions.gv.backOffice` a proposed back-office value). `tokens.css` holds every token's value on `:root`; the back-office values go only to `tokens.meta.json`, for the Proposal page. Storybook and the workbench load the tokens; the app does not. An unreadable source warns and keeps the committed outputs (exit 0). `-- --check` exits 1 when an output would change, a name breaks `/^--gv-[a-z0-9-]+$/` or the source is broken.
- `npm run ds:check`: `ds:tokens -- --check`, `ds:lint`, then `ds:a11y -- --check`. The last reads the committed `.storybook/static/a11y-results.json` and exits 1 on a critical axe violation in a `Components/` story that is not in `a11y-known.json` (story id and rule), on a listed one that no longer fails, or when the results file is missing; it prints how many known ones remain. So it passes unless a change adds a critical; fixing a known one means removing its entry from `a11y-known.json`.
- `npm run ds:scan`: scan `app/` for component usages (library components, plus one component per directory with an index file under `app/components/UI/` and `app/components/admin/`), off-spec values and legacy/token reads, map files to routes, score components and pages. Writes `.storybook/static/design-scan.json` (git-ignored) and `.storybook/static/design-scan.summary.json` (committed, for the trend). Accepted findings live in `scan.allow.json`. Exits 0 on findings, with no git and with no `tokens.meta.json`; only a crash exits 1.
- `npm run ds:lint`: off-spec values (px, hex, rgba, named colours, layout spacing) on lines added under `app/component-library/` and `app/design-system/` since the merge-base with `master` (or `origin/master`, or `-- --base <ref>`), printed as `file:line raw → nearest token`. Exits 1 if any.
- `npm run ds:changes [-- --base <ref>]`: write `.storybook/static/design-changes.json` (committed) for the Review page: the commits since the merge-base with `master` (else `origin/master`, else the `mergeBase` that `ds:scan` caches in `design-scan.summary.json`), each with subject, body, changed files, a kind (`heal`, `lift`, `token`, `story` or `other`, from the `design-system(<area>)` prefix), the component named after the colon, and the offSpec delta when the commit refreshed the scan summary; plus the token value changes between `tokens.source.json` at the base and at `HEAD`. Messages go to `warnings`. The CI build clones with `--depth 1` and reaches no base, so when no base is found and the file exists, it keeps the committed file unchanged (a warning says so); refresh and commit it locally after branch changes. It always exits 0. It then writes `.storybook/static/trend.json` (committed) for the Proposal page: the scan totals at every commit that refreshed the scan summary, oldest first (`trend.ts`).
- `npm run ds:routes-fixture [-- --host <url>]`: refresh `.storybook/static/routes.fixture.json` (committed), the real ids and slugs the Review page puts into `$param` route segments, from the test tenant's public API (unauthenticated GET requests; the default host is this branch's epic preview, `pr-15027`, which is temporary: pass `--host` for another). `paths` overrides a param for one route where the name means another record (`ideas/$slug`). It prints the params it could not fill (admin-only records such as groups and campaigns); fill those by hand, later runs keep them. Run it after the tenant is reseeded; the build never runs it.
- `npm run ds:a11y [-- --url <storybook>] [--stories <glob,glob>] [--workers N]`: run axe (WCAG 2.0, 2.1 and 2.2, A and AA) on every story, or the story ids `--stories` matches, at 1280x900, against a running Storybook (default `http://localhost:6006`). Writes `.storybook/static/a11y-results.json` (committed); a filtered run keeps the other stories' results. `-- --check` reads that file without a browser (see `ds:check`). Known criticals live in `a11y-known.json`; per component checklists with the criteria axe cannot check are the `a11y.json` files next to the stories. Needs Playwright.
- `npm run ds:visual -- --baseline <dir>` / `-- --compare <dir>`: screenshot every story at 1280x900 and 390x844 and save a baseline or compare to one. Options: `--stories <glob,glob>`, `--allow-px N`, `--url <storybook>` (default `http://localhost:6006`), `--summary <file>`. A full compare writes the committed `.storybook/static/visual-summary.json`; a filtered run writes `<dir>/_summary.json`; `--summary` overrides both. A run over every story can need `NODE_OPTIONS=--max-old-space-size=4096`. Needs Playwright.
- `npm run ds:workbench`: build the workbench shell (`.storybook/workbench/`, React + Vite) into `.storybook/static/workbench/`, which Storybook copies into its output, so it is served at `<storybook>/workbench/`. It reads `design-scan.json`, `index.json` and the other data files at runtime from one level up; a missing one reads as empty. `npm run ds:workbench:typecheck` typechecks it (the app typecheck does not cover `.storybook/`).
- `npm run ds:smoke -- --dir <storybook output> [--screenshot <file.png>]`: serve a built Storybook locally, open `/workbench/` in Chromium and check that it opens Components, the nav, the redirects (`#/start` to Components, `#/foundations` to Colour), the pages and the console. `--review-host <platform origin>` also checks the Review page's platform frames: the build is served under `<origin>/storybook/` by request interception, so the frames are same origin. Needs Playwright (see `playwright.ts`: `GV_PLAYWRIGHT_DIR`, `PLAYWRIGHT_BROWSERS_PATH`).
- `npm run ds:prepare`: runs `ds:tokens`, `ds:scan` and `ds:changes` in order, then `ds:workbench` even if one of those failed; `build-storybook` and `storybook` run it first (npm pre-scripts are off in this repo). Every step must exit 0 even with missing inputs, a shallow clone or no `master` ref.
